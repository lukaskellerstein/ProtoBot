ProtoBot Fork Cheat Sheet

Your notes stay in your fork. Your code goes upstream. One picture, four rules, three commands.

Their code
Your feature
Your notes

Four rules

  1. 1 Start every feature from their main. Not from your main. Your main has your notes on it, and those notes would ride along into the pull request.
  2. 2 One feature, one worktree, one branch, one agent. Run as many at once as you like. Git will not let two of them share a branch, so they cannot tread on each other.
  3. 3 Your notes live on your main and travel nowhere. The lukas/ folder is committed to your fork's main and to nothing else. Worktrees never see it, so it can never leak.
  4. 4 Catch up before you start anything. Upstream moves several times a day. A branch cut from stale code means a painful rebase later.

Three things you type

Catch up

in ProtoBot/

git fetch upstream --prune
git rebase upstream/main
git push --force-with-lease \
  origin main

Start a feature

from anywhere

claude -w lukas/<slug>

# it makes
# .worktrees/lukas/<slug>
# from upstream/main

Ship it

in the worktree

pre-commit run --all-files
git push -u origin \
  lukas/<slug>
gh pr create \
  --repo redhat-et/protobot \
  --base main

Never

  • ×Cut a branch from origin/main. That is the one mistake that leaks your notes upstream.
  • ×Commit an upstream file to your main. It can never reach upstream from there, and your daily rebase starts conflicting.
  • ×Put a personal skill in .agents/skills/. That folder is upstream's. Use ~/.claude/skills/.
  • ×Press Sync fork on GitHub. It fights your rebase.
  • ×Use a plain git push --force. Always --force-with-lease.
